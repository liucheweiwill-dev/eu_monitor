# eu_monitor

一頁式的 Google 搜尋啟動器，用來每天掃三個歐盟／北約機構網站的最新動態。

**線上版**：<https://liucheweiwill-dev.github.io/eu_monitor/>

## 這是什麼

一個 `index.html`，沒有建置步驟、沒有依賴、沒有後端。按一個鈕，
用預先組好的查詢開三個 Google 分頁：

| 網站 | 查詢 |
|---|---|
| eeas.europa.eu | `site:eeas.europa.eu (關鍵字 OR 組)` + 時間篩選 |
| consilium.europa.eu | 同上 |
| nato.int | 同上 |

- **時間範圍**可切換：過去 24 小時 / 一週 / 一個月，**預設一週**
- **關鍵字可直接編輯**，存在瀏覽器 localStorage，不會回傳任何地方
- 多字或含連字號的關鍵字自動加引號（`Indo-Pacific` → `"Indo-Pacific"`）
- 關鍵字全部清空會退化成純 `site:` 查詢，等於「這站這段期間所有新東西」

## 為什麼預設是一週而不是一天

Google 收錄有延遲。用「過去 24 小時」會漏掉昨天發布、今天才被收錄的文章。
一週窗會重複看到熟悉的項目，但不會漏——對輿情蒐集而言，
**漏掉比重複嚴重得多**。

## 判讀提醒

搜尋結果為空只代表「這次查詢沒看到新項目」，**不代表這三站真的沒有新內容**。
Google 不保證每一頁都會被收錄。若某站長期都是空的，
先手動去該站官網列表對一次再下結論。

## 為什麼是這種做法

先前曾嘗試用 Brave Search API 自建網頁做同樣的事
（見 <https://github.com/liucheweiwill-dev/NewsSearch>），
結論是做不到時間排序的監看：Brave 索引得到目標文章，但機構網站的頁面
大多沒有 `page_age`，而 Brave 的 `freshness` 參數正是依該欄位篩選，
因此在定義上就會排除沒有日期的文章。RSS 也不可行——這三站都沒有 feed。

Google 做得到，因為它對機構網站的刊登日期推導積極得多。
所以這裡不再重建搜尋層，直接用已經被證實可行的東西：Google 的介面加人的眼睛。
判斷哪些重要仍然由人做——那正是這件事的價值所在。

## 要改這個工具的話

先讀 [`docs/AGENT_BRIEF.md`](docs/AGENT_BRIEF.md)。那份文件記錄了四條已經走過的死路
（Brave `freshness`、日期字串注入、RSS、深分頁）與它們的實測證據，
以及哪些設計約束不能破壞、什麼情況才值得做大改。
這個工具長成現在這樣是有原因的，不先看會重走一遍。
